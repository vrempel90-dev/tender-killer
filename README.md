# TENDER KILLER

AI-платформа анализа государственных и корпоративных закупок Казахстана.

> **Статус после аудита 15.10.2026:** проект продолжен, критичные пути доступа
> и финансового переноса исправлены. К коммерческому запуску **не готов**.
> Актуальные результаты: [аудит](docs/audit-2026-10-15.md),
> [безопасность](docs/security-foundation.md), [финансы/E2E](docs/finance-corrections.md),
> [ограничения AI](docs/ai-integrity.md), [release gates](docs/release-gates.md).
> Ниже сохранено описание исходных модулей; оно не является подтверждением
> полной готовности.
> Локальный AI и актуальные проверки: [Ollama / Qwen3](docs/local-ai.md),
> [отчёт испытаний 16.10.2026](docs/local-ai-evaluation.md). Production deployment не выполнялся.
Отвечает поставщику на пять вопросов до подачи заявки:

1. Стоит ли участвовать в конкретном тендере?
2. Сколько компания реально заработает после всех расходов и налогов?
3. Какие ошибки и несоответствия есть в документах заявки?
4. Какова подтверждённая закупочная стоимость и где её взять?
5. Какие финансовые, договорные и конкурентные риски есть у сделки?

Интерфейс на русском языке, расчёты в тенге (₸).

## Требования

* **Node.js** 20.9+ (проверено на 22.x)
* **PostgreSQL** 14+
* **npm** 10+

Опционально:

* **Ollama + Qwen3 8B/4B** — AI по умолчанию, без платного API. Модель устанавливает администратор отдельной командой; [запуск и безопасность](docs/local-ai.md).
* **Anthropic API-ключ** — опциональный внешний provider, только после явного выбора и разрешения владельца. Ошибка Ollama не включает его автоматически.
* **Docker** — для запуска в контейнере.

## Быстрый старт

```bash
# 1. Зависимости
npm install

# 2. Конфигурация
cp .env.example .env
#    Обязательно задайте DATABASE_URL, SESSION_SECRET и APP_URL.
#    Для документов настройте CLAMAV_HOST / DOCUMENT_SCAN_MODE.
#    Сгенерировать секрет: openssl rand -base64 48

# 3. База данных: применить миграции и загрузить справочник налоговых ставок
npm run db:deploy
npm run db:seed

# 4. Запуск
npm run dev
```

Приложение откроется на <http://localhost:3000>. Первый экран — регистрация
компании: укажите налоговый режим, от него зависит расчёт НДС и налога на доход.

### Запуск в production-режиме

```bash
npm run build      # сборка; статика автоматически копируется в .next/standalone
npm start          # запуск собранного сервера
```

`npm start` запускает `node .next/standalone/server.js`, а не `next start`:
при `output: 'standalone'` второй вариант не отдаёт статику. Порт задаётся
переменной `PORT` (по умолчанию 3000).

### Проверка сборки и тестов

```bash
npm run verify     # типы + линтер + тесты
npm run test       # только автотесты
npm run build      # production-сборка
```

### Что проверено

Установка с нуля (миграции → справочник ставок → запуск → регистрация
компании) проверена на чистой базе данных. Все 18 страниц приложения
проверены в браузере Chromium на разрешениях 1440×900 и 390×844:
ошибок в консоли и горизонтальной прокрутки нет.

## Автономная установка на сервере покупателя (без платных AI API)

**Инструкция:** [docs/SELF_HOSTED_INSTALL.md](docs/SELF_HOSTED_INSTALL.md).

В `docker-compose.yml` входят Next.js, PostgreSQL, **Ollama + Qwen3**, настоящий **ClamAV**, отдельные миграции и минимально привилегированная роль БД. БД, AI и антивирус не имеют публичных портов; документы, модели и сигнатуры ClamAV находятся в постоянных томах.

```bash
cp .env.example .env    # установите уникальные пароли и ключи
chmod 600 .env
# Выберите в .env OLLAMA_MODEL=qwen3:4b или qwen3:8b
docker compose up -d --build
# Модель ставится отдельно, чтобы не скачивать её при каждом запуске:
docker compose -f docker-compose.yml -f docker-compose.model-install.yml run --rm --no-deps model-install qwen3:4b
docker compose exec ollama ollama list
```

**Важные условия:**
- В self-host Compose `AI_PROVIDER=ollama`, внешний AI отключён; OpenAI/Codex/Anthropic API-ключи не нужны. Требуется собственное оборудование, соответствующее модели; это *не обещание бесплатного облачного хостинга*.
- ClamAV обязателен и может несколько минут загружать сигнатуры при первом старте.
- Без официального токена доступа к порталам RADAR/GUARD используют импорт CSV/XLSX и ручное сравнение редакций, а не фоновое сканирование госпорталов.
- Восстановление пароля по email требует настроенного и подтверждённого отправителя. Без него сервис честно возвращает ошибку 503; тестовая отправка не выдаётся за доставку.
- Production на Railway остаётся на прежнем релизе: этот PR не переключает ветку/миграции и не создаёт платных сервисов.

### Railway

Развёртывание на Railway **не является бесплатным по CPU/RAM**; даже в Pro лимит включённого потребления $20 применяется ко всему workspace. До отдельного разрешения владельца не развертывать Ollama/ClamAV и не применять миграции к рабочей БД. См. [план обновления](docs/production-update-plan.md).

## Как устроен финансовый модуль

Это ядро продукта. Подробное описание модели — [`docs/finance-model.md`](docs/finance-model.md).

Принципы, заложенные в расчёт:

* **Прибыль ≠ денежный поток.** Считаются отдельно, расхождение показывается
  с объяснением причин (НДС, залоги, сроки платежей).
* **Возвратный залог — не расход.** В себестоимость попадает только стоимость
  обеспечения: комиссия банка за гарантию или стоимость замороженных денег.
* **Входящий НДС возмещается не всегда.** Зачёт возможен только у плательщика
  НДС и только в своей доле; невозмещаемая часть — реальный расход.
* **Налоговый режим меняет арифметику.** На СНР налог считается с оборота,
  поэтому убыточная сделка всё равно создаёт налог, а безубыточная цена выше.
* **Деньги в целых тиын.** Все суммы хранятся и считаются в минорных единицах
  (1 ₸ = 100 тиын), что исключает накопление ошибок округления.
* **Нет выдуманных значений.** Незаполненные поля показываются пустыми и
  попадают в список недостающих данных с перечнем показателей, которые без
  них не считаются.
* **Каждый показатель объясняется.** Для всех ключевых метрик возвращается
  формула, подстановка фактических значений, смысл и оговорки.

### Что рассчитывается

Выручка (с НДС и без), полная себестоимость исполнения, валовая/операционная/
чистая прибыль, рентабельность продаж, ROI (с явной формулой и приведением к
году), минимальная безубыточная цена, цена под целевую прибыль, потребность в
оборотном капитале, пиковый кассовый разрыв с датой, стоимость финансирования,
прогноз ДДС по дням, чувствительность к снижению цены и росту затрат,
три сценария (оптимистичный / базовый / стрессовый).

### Налоговые ставки

Ставки — **конфигурация, а не константы**. Каждая запись содержит источник,
дату начала действия и примечание. Значения по умолчанию загружаются командой
`npm run db:seed` из `src/lib/finance/tax-config.ts` в таблицу
`tax_rate_configs`, после чего их можно править.

Ставки, не сверённые с официальным текстом нормы, помечены
`⚠️ ТРЕБУЕТ СВЕРКИ С ПЕРВОИСТОЧНИКОМ` и видны в разделе «Настройки → Налоги».
Подробнее — [`docs/tax-config.md`](docs/tax-config.md).

## Безопасность

* Авторизация: новые пароли хешируются Argon2id, старые bcrypt-хеши читаются в режиме миграции; сессия — подписанный JWT
  в `httpOnly`-cookie плюс серверный реестр сессий, который позволяет их отзывать.
* Изоляция данных: tenant-scope и PostgreSQL RLS с ограниченной DB-ролью; каждая выборка фильтруется по `companyId` из сессии.
  Идентификатор компании никогда не принимается от клиента.
* Разграничение доступа: роли `OWNER`, `ADMIN`, `ANALYST`, `VIEWER`;
  проверка выполняется на сервере, а не только в интерфейсе.
* Журнал операций: изменения данных, загрузка и удаление документов, запуски
  AI-анализа пишутся в `audit_logs`.
* Документы: хранятся вне репозитория в каталоге `STORAGE_DIR`
  (по умолчанию `./storage`, исключён из Git). Новые документы шифруются AES-256-GCM, проверяются тип, размер и обязательный антивирусный вердикт ClamAV.
* Секреты: только в переменных окружения. `.env` в Git не попадает,
  в репозитории лежит лишь `.env.example` без значений.
