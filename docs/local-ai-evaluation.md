# Испытания локального AI — 16.10.2026

Интеграция проверена с реально работающей Ollama 0.33.3 и ранее установленными `qwen3:4b` / `qwen3:8b`. Платные API не вызывались, модели в ходе работы не скачивались. Проверена production-сборка приложения, запущенная локально с отдельной PostgreSQL и ограниченной NOBYPASSRLS-ролью. Это не production deployment.

## Корпус и воспроизведение

Один и тот же набор открытых документов Самрук-Казына использован для обеих моделей:

| Источник | Выбранная часть | Размер извлечённого текста |
|---|---|---:|
| [Договор 1163451/2025/1, стикеры](https://zakup.sk.kz/eprocfilestorage/open-api/files/download/f774e1ae-b3c3-48fb-8763-b488329a9e23-2025-mdb) | Полная русскоязычная техспецификация, стр. 35 | 1542 символа |
| [Договор 1107119/2025/1, сальники](https://zakup.sk.kz/eprocfilestorage/open-api/files/download/54437cb6-c54d-463c-828a-7d0dc993e489-2025-mdb) | Полная русскоязычная техспецификация, стр. 36 | 2484 символа |

Это две выбранные страницы из договоров на 38/40 страниц, а не анализ полных договоров. Выбор сделан явно; большая часть исходных PDF в этот эксперимент не входила. Все символы выбранных страниц обработаны последовательно с перекрытием (по два фрагмента на документ). Данные публичные; частные документы компаний не использовались.

Скрипт `scripts/evaluate-local-ai.ts` использует реальные REST-вызовы provider, существующую Zod-схему требований, проверку цитат и числовой опоры. Он не подменяет модель mock-ответами, не меняет финансовые данные и не обходит HTTP-авторизацию приложения: это отдельный административный benchmark адаптера. Полный путь авторизации/квот/сохранения дополнительно проверен сквозным HTTP-тестом ниже.

Для повторения скачайте оригиналы отдельно и задайте пути в `docs/local-ai-corpus.example.json`:

```sh
npx tsx scripts/evaluate-local-ai.ts docs/local-ai-corpus.example.json report.json
```

SHA-256 оригиналов, model digest и результаты по документам сохранены в [исходном замере](local-ai-baseline-measurements.json) и [замере после настройки памяти](local-ai-optimized-measurements.json). Prompt version: `2.0.0-local`; температура 0, thinking выключен, JSON Schema в `format`, контекст 16384, ответ до 2048 токенов. Теги моделей изменяемы: повторение требует сверять digest, а не только имя.

## Результаты на GPU после настройки памяти

Хост: Windows, Intel Core i5-14400F (16 логических CPU), 31,7 ГиБ физической RAM по `os.totalmem()`; NVIDIA RTX 3070 Ti, 8 ГиБ VRAM. Один запрос и одна загруженная модель. `OLLAMA_FLASH_ATTENTION=1`, `OLLAMA_KV_CACHE_TYPE=q8_0`, RAM-кэш промптов ограничен 256 МиБ.

| Метрика, два документа | Qwen3 4B | Qwen3 8B |
|---|---:|---:|
| Корректная структура, завершённый JSON + Zod | 4/4 (100%) | 4/4 (100%) |
| Извлечено записей до ручной проверки | 21 | 33 |
| Цитаты найдены в выбранном исходном тексте | 18/21 (85,7%) | 33/33 (100%) |
| Выводы без подтверждённой цитаты | 3 | 0 |
| Числа формулировок, отсутствующие в собственной цитате | 0 | 0 |
| Покрытие десяти контрольных требований | 9/10 (90%) | 9/10 (90%) |
| Время первой / второй спецификации | 11,408 / 13,317 с | 27,271 / 36,979 с |
| Суммарное время | 24,725 с | 64,250 с |
| Выделенная память модели через `/api/ps` | 3,69 ГиБ | 5,84 ГиБ |
| Из неё в GPU | 3,69 ГиБ | 5,84 ГиБ |

Контрольный перечень задан до запуска: сроки, DDP, оплата, размер/листы стикера; состав комплекта, материал, армирование, срок и DDP для сальников. Это небольшой набор контрольных пунктов, а не исчерпывающая экспертная разметка всех требований. Автоматическое покрытие ищется по фразам/числам и само по себе не является оценкой смысловой точности.

**Смысловая точность не аттестована.** Просмотр ответов выявил реквизиты/подвалы, ошибочно названные требованиями, неверную классификацию срока, повторяющиеся записи. В 4B также встречались перечисления квалификационных условий из системной инструкции, которых нет в документе: проверка цитат их отклоняет. У 8B совпадающие цитаты могут сопровождать неправильное толкование. Нулевое число неподтверждённых цитат не означает отсутствие ошибочных выводов. Проверка чисел устанавливает наличие числовой опоры, а не юридический смысл или правильную привязку к сроку/обязательству.

Обе модели пропустили DDP в спецификации стикеров в оптимизированном прогоне. Полнота не гарантируется. Равенство платным сервисам не измерялось и не заявляется. По этой выборке 8B оставлена основной из-за лучшей опоры на цитаты, 4B — явно выбираемым облегчённым режимом; автоматического переключения между ними нет.

## Наблюдение до настройки памяти

С `f16` KV-кэшем: 4B — 44,825 с, 13/17 найденных цитат; 8B — 227,844 с, 25/26 найденных цитат. Выделенная память: 4,75 / 7,28 ГиБ; 8B частично находилась в системной памяти. После настройки обе модели полностью поместились в GPU; в логе подтверждены все 37 слоёв 8B в GPU.

Исходный прогон пересекался со сборкой/проверкой приложения, поэтому это наблюдение оптимизации, а не строгий контролируемый speedup. После настройки не было одновременных AI-запросов приложения. Параметры KV-кэша повлияли и на ответы; качество пересчитано, равнозначность двух режимов не предполагается. Время включает загрузку модели при переключении. Повторений и доверительных интервалов нет.

## Работа без GPU и оборудование

GPU был явно выключен (`CUDA_VISIBLE_DEVICES=-1`, Vulkan выключен). Для обеих моделей выполнен настоящий короткий структурированный тест; `/api/ps` подтвердил `size_vram=0`.

| Режим | Короткий JSON-тест, включая загрузку | Выделенная память модели |
|---|---:|---:|
| CPU, Qwen3 4B | 3,687 с | 3,70 ГиБ |
| CPU, Qwen3 8B | 5,590 с | 6,28 ГиБ |

Полный корпус на CPU не прогонялся: эти времена нельзя использовать как время анализа документа. Минимальная RAM, пиковый RSS всех процессов, серверная нагрузка нескольких компаний и скорость на иных CPU/GPU не установлены. `/api/ps` показывает выделенную память модели, а не пик памяти ОС. Измерения подтверждают работоспособность на указанном хосте с 32 ГБ RAM / 8 ГБ VRAM, а не достаточность меньшей конфигурации. К модели добавляются память ОС, PostgreSQL, Next.js, парсера и резерв.

## Приложение, автоматические проверки и границы

- TypeScript, ESLint и production build проходят без ключей AI и без подключения к рабочей БД.
- Unit: 473 PASS и одна пропущенная POSIX-проверка прав файлов на Windows. POSIX-проверка остаётся активной в Linux CI; Windows ACL этим тестом не удостоверяются.
- Все 11 миграций применены на отдельной PostgreSQL; RLS проверена под ограниченной ролью. Новые AI-таблицы входят в проверяемый реестр tenant-таблиц.
- Итоговый единый прогон: 43 HTTP/browser-теста PASS (42 сценария безопасности, MFA, RLS, RADAR/GUARD и SQL-очереди плюс один полный сценарий с настоящей моделью). В загрузочных сценариях использован явно тестовый ClamAV protocol stub. Настоящий антивирус и Docker runtime этим прогоном не проверены.
- Сквозной тест с настоящим Qwen3 8B прошёл: публичный PDF → штатное извлечение текста → вход/MFA → требования → товарные позиции → compliance → анализ условий → сохранённые фрагменты и модель → проверка чужой компании/Viewer → кнопка подключения в браузере. Для этого сценария взят [публичный технический документ закупки 510615](https://zakup.sk.kz/eprocfilestorage/open-api/files/download/9ee72e59-db9c-4d2d-a4b1-fa02388399d7-2020-mdb), 1937 символов, одна страница. Анализ условий на техническом приложении не заменяет испытание полноценного юридического договора.
- Проверены ошибки сервера/модели, незавершённые ответы, неверные JSON/Zod, неподтверждённые цитаты и числа, известные prompt-injection шаблоны, секреты, квоты, отмена/таймаут, контекст, частичные результаты, смена digest, отсутствие платного fallback. Запрет чтения новых semantic endpoints из другой компании проверяется в RADAR/GUARD тестах.
- Финансовый движок не изменён. Все AI-результаты требуют подтверждения; подтверждённые закупочные цены/тендеры/поставщики моделью не создаются.

Docker YAML, приватная AI-сеть, отсутствие опубликованного 11434 и явный installer проверены статически. Официальный тег `ollama/ollama:0.33.3` существует; контейнеры не запускались, поскольку Docker на хосте отсутствует. Перед merge/эксплуатацией ещё нужны контейнерный прогон, проверка целевой инфраструктуры/реального антивируса и расширенная экспертная оценка качества на репрезентативном корпусе. Полная готовность к production не заявляется.

Работа выполнена в `codex/local-ai-ollama` от HEAD PR #1 `96f32ab`. Другая локальная копия с 39 незакоммиченными файлами и собственными коммитами RADAR/GUARD не изменялась и в эту ветку не переносилась. Merge и production deployment не выполнялись.
