## Что реализовано и проверено

### Инфраструктура
* Next.js 16 + React 19 + TypeScript в строгом режиме
  (`noUncheckedIndexedAccess`).
* PostgreSQL + Prisma 7 через драйвер-адаптер `@prisma/adapter-pg`.
* Tailwind CSS 4, дизайн-система в `src/components/ui`.
* ESLint 9 (flat config), Vitest — **213 автотестов**.
* Docker (standalone, непривилегированный пользователь, том для документов,
  шрифт DejaVu для PDF) и `docker compose` с автоприменением миграций.
* `/api/health` для Docker и Railway.
* Обработчики ошибок и «не найдено» с понятными сообщениями вместо пустых
  экранов.

### Безопасность — проверено запросами
* Регистрация и вход; bcrypt (12 раундов); сессия в `httpOnly`-cookie плюс
  серверный реестр сессий с отзывом.
* **Изоляция данных компаний проверена**: вторая компания не получает ни
  тендеры, ни документы, ни расчёты, ни отчёты первой — ни через API, ни
  через страницы (404 / «не найдено»).
* **Роли проверены**: `VIEWER` не может создавать тендеры, менять налоговые
  ставки и открывать журнал операций; вместо ошибки показывается понятное
  сообщение о недостатке прав.
* Налоговый режим, не допускающий статус плательщика НДС, принудительно его
  снимает (проверено: компания на СНР получает `isVatPayer = false`).
* Проверка типа, расширения, размера и имени загружаемого файла;
  дедупликация по SHA-256; защита от выхода за пределы каталога хранения.
* Журнал операций `audit_logs`.
* Секреты только в переменных окружения; `.env` и `storage/` исключены из Git.

### Модуль №1 — Financial Intelligence
Полный расчёт экономики тендера:

* выручка с разделением НДС, с учётом статуса плательщика;
* полная себестоимость: товары, прочие прямые, логистика, таможня, ФОТ и
  налоги с ФОТ, субподряд, накладные, резерв, невозмещаемый НДС, банковские
  комиссии, проценты по займу, стоимость обеспечений, гарантийный резерв;
* валовая, операционная, чистая прибыль; рентабельность продаж;
* ROI с явной формулой и приведением к году;
* минимальная безубыточная цена и цена под целевую прибыль (численное
  решение с точностью до 1 тиына);
* потребность в оборотном капитале, пиковый кассовый разрыв с датой;
* стоимость финансирования, включая автоматический расчёт из разрыва;
* прогноз ДДС по дням с расшифровкой каждого движения;
* чувствительность к снижению цены и росту затрат;
* три сценария с показом параметров;
* расшифровка формул для 12 ключевых показателей;
* список недостающих данных и предупреждения о типичных ошибках;
* налоговые ставки как конфигурация с источником и датой актуальности.

Контрольный пример проверен вручную — см. `docs/finance-model.md`.

### Модуль №2 — AI Compliance Checker
* Загрузка PDF, DOCX, XLSX; извлечение текста с разметкой по страницам,
  таблиц из DOCX и листов XLSX (с вычисленными значениями формул).
* **Страницы без текстового слоя отмечаются как непрочитанные**; статус
  извлечения `PARTIAL` или `FAILED`. Отсутствие текста никогда не трактуется
  как отсутствие документа.
* Извлечение требований закупки с цитатой и номером страницы;
  подтверждение требований пользователем.
* Проверка документов заявки со статусами «Подтверждено», «Не обнаружено»,
  «Несоответствие», «Требует проверки».
* **Защита от вымышленных фактов** (`src/lib/ai/verify.ts`):
  цитата проверяется поиском по тексту; номер страницы берётся из поиска;
  вывод без подтверждённой цитаты понижается до «Требует проверки»;
  «Не обнаружено» запрещён, если документ прочитан не полностью.
* Гарантий допуска к закупке не даётся.

### Модуль №3 — Tender Intelligence
* Импорт завершённых закупок из CSV и XLSX с автоматическим распознаванием
  12 колонок по заголовкам (проверено на реальном файле: распознаны все).
* Разбор денежных сумм в разных форматах, дат, видов процедур, БИН.
* Статистика снижения цены (среднее, медиана, минимум, максимум) с явным
  указанием размера выборки; записи без пары цен исключаются и
  пересчитываются отдельно.
* Выборка меньше 5 записей помечается как недостаточная для выводов.
* Анализ победителей и заказчиков.
* Моделирование допустимых ценовых предложений: историческое снижение
  сопоставляется с собственной безубыточной ценой; для каждого варианта
  указано основание.
* **Статистика не выдаётся за вероятность победы** — предупреждение
  выводится всегда. Фиктивные данные о закупках не создаются.

### Модуль №4 — AI Sourcing
* Позиции закупки с подтверждением пользователем; извлечение из
  спецификации через AI.
* Коммерческие предложения поставщиков с документом-основанием;
  предложение без документа помечается как неподтверждённое.
* Расчёт полной закупочной себестоимости с логистикой и таможней.
* Курс валюты не подставляется автоматически: без него себестоимость не
  рассчитывается.
* Сравнение предложений: автоматически выбирается только подтверждённое,
  соответствующее требованиям и не просроченное.
* Подтверждённые цены передаются в финансовую модель.
* Генерация запроса коммерческого предложения из данных тендера.

### Модуль №5 — Contract Risk Analyzer
* Анализ порядка оплаты, аванса, сроков, штрафов, обеспечения, гарантий,
  приёмки, расторжения, дополнительных расходов.
* Ссылки на пункты договора и цитаты.
* Числовые условия извлекаются только если прямо указаны, и переносятся в
  финансовую модель.
* Юридически неоднозначные условия отмечаются как требующие юриста.

### Отчёт для принятия решения
* Сводит экономику, денежный поток, проверку документов, риски договора,
  подтверждённость закупочных цен.
* Отдельный раздел «чего не хватает».
* Итоговая оценка: приемлемо / высокий риск / не рекомендуется /
  недостаточно данных.
* Выгрузка PDF (проверено: кириллица читается, 2 страницы) и печать.
* Сохранение снимка отчёта.

## Что не поддерживается

Перечислено честно, без обещаний:

* **Распознавание сканов (OCR)** не выполняется. Страницы-изображения
  помечаются как непрочитанные.
* **Автоматическая загрузка данных с порталов закупок** не реализована:
  подключение к API требует законного доступа и токенов. Модуль №3 работает
  на файлах, которые импортирует пользователь.
* **Приглашение новых пользователей** в компанию: роли и проверка прав
  работают, но интерфейс приглашения не сделан — учётную запись создаёт
  владелец при регистрации.
* **Автоматическая отправка запросов КП поставщикам** по почте: текст
  запроса формируется и копируется, отправку выполняет пользователь.
* **Прогноз вероятности победы** намеренно не реализован: исторические
  данные описывают прошлое и не дают оснований для такой оценки.
