# Передача TENDER KILLER покупателю — перечень активов и процедура

> Для полной продажи программного актива, а не действующего SaaS-бизнеса. Стартовая запрашиваемая цена владельца: **500 000 KZT**; она не является независимой рыночной оценкой. Подписание договора и уступка прав — только решением владельца.

## 1. Что готово к демонстрации как код

- Next.js / TypeScript / PostgreSQL / Prisma, финансовый движок, отчёты, аутентификация и MFA.
- AI Compliance, Contract Risk, Sourcing через локальные Ollama + Qwen3 (при установленной модели).
- Tender Intelligence и RADAR на импортированных CSV/XLSX, GUARD на документированных вручную редакциях.
- Подготовленный комплект самохостинга (Docker Compose), обязательный ClamAV, постоянное хранилище.
- Восстановление пароля с одноразовой ссылкой (для реальной доставки нужен подтверждённый email).
- GitHub Actions / unit / HTTP-browser / security checks. Финальный статус см. [аудит](FINAL-PROJECT-AUDIT.md).

**Не рекламировать:** автоматическое подключение к официальным госзакупкам без токена, 100% полноту и юридическую точность AI, готовую email-доставку без домена, OCR сканов, подтверждённых платящих клиентов или готовность к коммерческой эксплуатации в Казахстане.

## 2. Что передаётся по договору

1. Указанный SHA релиза, перечисленные принадлежащие продавцу исходные файлы и документация.
2. Принадлежащие продавцу исключительные имущественные права в объёме, описанном договором.
3. Инструкции по развертыванию на собственном оборудовании, структуру БД, применимые миграции и конфигурационные шаблоны без секретов.
4. Условия использования названия TENDER KILLER и дизайна в объёме, который действительно принадлежит продавцу.
5. Отдельно — список сторонних компонентов/моделей и их лицензий. Собственные права на OSS и модель покупателю не уступаются.

**Не передаются автоматически:** личные GitHub/Railway аккаунты, личный WhatsApp, платные подписки, ключи, приватные env-файлы, реальные данные других компаний, история переписки и токены. Для GitHub предпочтителен чистый репозиторий/архив на релизном SHA и передача в принадлежащую покупателю организацию.

## 3. Безопасная последовательность

1. Демо с **синтетической БД** и публичными/обезличенными тендерными файлами.
2. Проверка действующего юридического лица покупателя и полномочий подписанта.
3. NDA перед раскрытием дополнительных закрытых сведений (учтите: текущий GitHub-репозиторий публичный; NDA не делает опубликованное ранее закрытым).
4. Технический due diligence с фиксацией открытых ограничений. Для проверки кода предоставляйте конкретный commit SHA без личных токенов.
5. Договор отчуждения имущественных прав и акт приёма-передачи; согласованное обеспечение оплаты (возможна эскроу-механика по отдельному соглашению).
6. Подтверждение получения платежа по условиям договора.
7. Передача исходников, документации и контрольных SHA; помощь в локальной установке только в отдельно согласованном объёме.
8. Покупатель сам создаёт новые PostgreSQL пароли, SESSION_SECRET, DOCUMENT_ENCRYPTION_KEY, домен, email и публичный TLS-сертификат. Он оплачивает собственное оборудование и эксплуатацию.

## 5. Критичные юридические и эксплуатационные вопросы

- Программа объявлена proprietary в README, но репозиторий **публичен**. Публичность не делает код автоматически открыто-лицензионным, но ранее опубликованные копии не контролируются продавцом.
- Составить лицензируемый SBOM / перечень обязательств open source. Проверить право передачи всего собственного кода и использованных изображений, шрифтов, марок, AI-моделей и ресурсов третьих лиц. Уточнить конкретные лицензии и notice-требования перед сделкой.
- Казахстанские требования к персональным данным, локализации, трансграничной обработке и резервным копиям требуют профессиональной правовой проверки до коммерческой эксплуатации.
- Никакая продажа ПО сама по себе не гарантирует работающий API госзакупок — покупатель должен получить доступ законным путём.
