Это не готовая коммерческая платформа и не заключение о соответствии ASVS.

## Результаты

Итоговый локальный прогон: TypeScript PASS, ESLint PASS, 234 Vitest PASS,
8 Playwright HTTP/browser PASS. Production build без секретов PASS.
Четыре миграции применены на отдельном локальном PostgreSQL.

- Исправлены нарушения изоляции модели/налогов; проверки прав и отзыв сессий
  подтверждены HTTP-тестами на PostgreSQL.
- Реальные PDF/DOCX/XLSX проходят ограниченный импорт; исходные bytes/hash
  сохраняются. Новый worker не получает секреты и имеет лимиты heap/time.
- До parser есть проверка Office-контейнера и ClamAV gate. Протокол антивируса
  проверен тестовым TCP stub; реальный ClamAV daemon здесь не запускался.
- Денежные операции переведены на decimal helpers, валютные КП и НДС поставщика
  сохраняют смысл. Неполная цена/себестоимость возвращает MISSING.
- Проверен браузерный путь с настоящим публичным PDF и явно тестовым КП,
  включая PDF-экспорт, сохранение и повторный вход. Реальный коммерческий КП
  и живой AI в этом сценарии отсутствовали.
- Production build выполняется без DB/API/session credentials; DB создаётся
  лениво и требует корректной конфигурации при реальной операции.
- Подготовлены CI: unit/types/lint/build, HTTP tests, CodeQL, Gitleaks,
  npm audit и контейнерный Trivy. До фактического запуска GitHub checks
  их нельзя считать пройденными.

## Deployment

Docker не запускался локально: engine не установлен; Linux build выполняется в CI. Migration/seed
вынесены в одноразовый builder service. Worker production dependencies копируются
явно, runtime не содержит npm и peer migration CLI. Добавлен container smoke
без сети, с read-only FS, cap-drop и no-new-privileges. Приложение остаётся
непривилегированным. DB/Redis не публикуются наружу;
приложение Compose связано с loopback. Нужен отдельный TLS ingress.

`POSTGRES_PASSWORD` обязателен; для URL используйте корректно закодированный
пароль (случайный hex подходит). `APP_URL` должен совпадать с браузерным origin;
для production вне loopback обязателен HTTPS. Подключение к production,
изменение branch protection, merge и deployment этой работой не выполнялись.

В GitHub нужно назначить Quality/Security required checks и защиту основной
ветки после проверки workflow владельцем. Текущая основная ветка репозитория —
`claude/laughing-heisenberg-2wdj8t`; ветки main в качестве цели не предполагается.
