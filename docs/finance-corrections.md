# Финансовые исправления — движок 1.1.0

Суммы остаются в целых тиын. Конвертация, проценты, НДС, проценты по займу,
стоимость позиций и основные сценарные умножения выполняются decimal.js
с точностью 40 знаков и ROUND_HALF_UP. NaN/Infinity/переполнение больше не
подменяются нулём: запрос получает ошибку. Решатель возвращает недостижимость
в пределах безопасного диапазона, а не расширяет цену за границы Number.

Выбранная цена КП переводится из валюты предложения в KZT и сохраняет режим
НДС. Нет допустимого курса, истёк срок, неизвестно соответствие или нет
подтверждённого основания — позиция остаётся в `unpricedItems`, её отсутствие
не скрывается исключением из суммы. Отчёт использует тот же преобразователь.

API расчёта возвращает `status=MISSING`, `result=null` и список полей при
отсутствии цены/себестоимости. Такой расчёт не сохраняется. Остальные плановые
результаты имеют `status=ESTIMATED`; до заполнения сроков график ДДС скрыт.
Числовая структура низкоуровневого движка сохранена для совместимости;
публиковать её напрямую без статуса/проверки полноты нельзя.

В финансовой модели сохраняется `provenance`: значение, источник пользователя,
дата получения и один из статусов VERIFIED / USER_CONFIRMED / ESTIMATED /
MISSING / STALE. Ручной ввод не становится VERIFIED; нулевая затрата без
отдельного подтверждения остаётся ESTIMATED. Нормативные ставки и версии
собираются на сервере, корректировки компании изолированы. Это первый слой
Data Provenance; сквозные ссылки каждого AI-вывода и всех исторических величин
на документы/страницы ещё требуют дальнейшей работы.
