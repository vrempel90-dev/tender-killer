# Защита загруженных документов

Документ описывает, что происходит с файлом пользователя от загрузки до
выдачи, и что из этого ещё не закрыто. Состояние на 15.10.2026.

В документах тендеров лежат коммерческие условия, цены и персональные
данные. Поэтому файл — не «просто вложение», а самый чувствительный
объект в системе.

---

## 1. Путь файла при загрузке

Порядок проверок в `src/app/api/documents/upload/route.ts`:

| Шаг | Что проверяется | Что отклоняется |
| --- | --- | --- |
| 1 | право на запись (роль аналитика и выше) | чужая роль |
| 2 | аренда парсера на компанию | параллельный разбор, исчерпание CPU |
| 3 | общий лимит: 30 загрузок в час на компанию | массовая загрузка |
| 4 | размер тела запроса считается по факту чтения | подделанный Content-Length |
| 5 | принадлежность тендера компании из сессии | загрузка в чужой тендер |
| 6 | MIME-тип, расширение, соответствие между ними, имя файла | подмена типа, пути в имени |
| 7 | структура файла по байтам (`inspect.ts`) | не тот формат, ZIP-бомба, zip-slip, макросы, шифрованные элементы |
| 8 | антивирус (ClamAV, потоком) | заражённый файл |
| 9 | дедупликация по sha256 в пределах тендера | повторная загрузка |
| 10 | шифрование перед записью на диск | чтение файла с тома |
| 11 | разбор в изолированном worker с лимитами | зависание и переполнение парсера |

Байты файла живут в памяти запроса до вердикта антивируса: **заражённый
файл на диск не попадает**. Это строже карантина — нечего освобождать из
карантина и нечего забыть удалить.

Если запись в БД не удалась, файл с диска удаляется: «сирот» в хранилище
не остаётся.

## 2. Шифрование на диске

`src/lib/documents/encryption.ts`, AES-256-GCM.

Формат файла на диске: `TKENC1\n` + IV (12 байт) + тег (16 байт) +
шифротекст. Признак в начале нужен для совместимости: файлы, загруженные
до включения шифрования, читаются как есть.

Дополнительные аутентифицируемые данные (AAD) — путь файла в хранилище.
Следствие: **файл одной записи нельзя расшифровать как файл другой**.
Подмена файла между компаниями или между документами одной компании
обнаруживается тегом, а не сравнением содержимого.

Ключ — `DOCUMENT_ENCRYPTION_KEY`, 32 байта в base64
(`npm run keygen:documents`). Без ключа:

- в production и при `DOCUMENT_ENCRYPTION_MODE=required` загрузка
  документов **отключена** (503) — иначе файлы легли бы на диск открыто;
- в разработке файлы пишутся открыто, чтобы не требовать настройки для
  локального запуска.

Потеря ключа означает потерю доступа к уже загруженным документам.
Управление ключами (KMS, ротация, разные ключи на компанию) не сделано и
зависит от выбора хостинга — см. `docs/release-gates.md`.

## 3. Целостность при чтении

`readStoredFile(path, expectedSha256)` сверяет контрольную сумму
расшифрованного содержимого с той, что записана в БД при загрузке.

Зачем, если тег GCM уже защищает от подмены: тег подтверждает, что файл
не изменён относительно того, что было зашифровано для **этого пути**.
Сверка sha256 закрывает другой случай — рассинхрон «запись в БД одна, файл
другой» (сбой тома, ошибка восстановления из резервной копии, ручное
вмешательство). Пользователь не должен получить чужой или испорченный файл
под именем своего документа.

Сверка выполняется и при выдаче файла, и при повторном разборе.
Несовпадение — ошибка с понятным текстом, а не молча другой файл.

## 4. Права на файлы

Каталог компании создаётся с правами `0700`, файл — `0600`. Другие
пользователи системы не читают хранилище даже при доступе к машине.

Путь файла всегда приводится к абсолютному и проверяется на выход за
пределы `STORAGE_DIR` (`resolveStoragePath`). Имя файла пользователя
используется только для показа и для расширения; имя на диске — UUID.

## 5. Выдача файла

`GET /api/documents/[id]/download`:

- документ ищется по БД с фильтром по компании из сессии; путь из запроса
  не используется;
- `Content-Disposition: attachment` — браузер не отображает файл;
- `X-Content-Type-Options: nosniff` — тип не угадывается по содержимому;
- `Content-Security-Policy: default-src 'none'; sandbox` — даже при
  попытке отображения файл ничего не загружает и не исполняет;
- `Cache-Control: private, no-store` — файл не кэшируется посредниками.

## 6. Проверки

Модульные: `src/lib/documents/__tests__/encryption.test.ts` (15 тестов) —
длина и формат ключа, неразличимость содержимого, случайный IV, отказ при
подмене пути, обнаружение изменённого и обрезанного файла, поведение без
ключа в обоих режимах.

`src/lib/documents/__tests__/storage.integrity.test.ts` (7 тестов) — на
диск попадают зашифрованные байты, чтение возвращает исходное содержимое,
права 0700/0600, остановка выдачи при несовпадении sha256, обнаружение
подмены файла на диске, запрет выхода за каталог хранения.

Сквозная: `tests/security.spec.ts` — после загрузки через HTTP файл на
диске начинается с `TKENC1` и не содержит начала исходного PDF, а
скачивание возвращает байты с исходной контрольной суммой.

## 7. Что остаётся

| Работа | Почему не сделано |
| --- | --- |
| KMS и ротация ключей | зависит от выбора хостинга и региона |
| Отдельный ключ на компанию | требует решения по хранению ключей; сейчас один ключ на установку |
| Перешифрование файлов, загруженных до включения шифрования | нужен эксплуатационный скрипт и окно обслуживания |
| Изоляция парсера на уровне ОС | V8 worker не песочница ОС; нужен отдельный непривилегированный сервис |
| Распознавание сканов (OCR) | не поддерживается; документ без текстового слоя честно помечается непрочитанным |
