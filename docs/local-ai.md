# Локальный AI: Ollama и Qwen3

По умолчанию TENDER KILLER использует локальную `qwen3:8b`. Облегчённая модель — `qwen3:4b`. Ключи OpenAI/Anthropic и `AI_EXTERNAL_TRANSFER_APPROVED=true` для локальной обработки не нужны. Модели не загружаются сборкой, миграцией, health check или запуском приложения.

## Что подключено

`AIProvider` реализован в `src/lib/ai/provider.ts`; реализации — `OllamaProvider` и `AnthropicProvider`. Существующий `callStructured` сохранён. Требования, позиции, compliance и риски договора проходят прежние Zod-схемы и усиленную проверку цитат/чисел. JSON Schema передаётся в `/api/chat` через `format`, `stream=false`, `think=false`, температура 0. Незавершённая генерация, другой model ID, некорректный JSON или Zod-ответ не становятся успешным анализом.

RADAR получил отдельное семантическое пояснение сопоставления с профилем; GUARD — пояснение двух сохранённых редакций. Это дополнительные действия по кнопке. Исходные правила поиска, оценки изменений, пересчёта и подтверждения сохраняются. `interpretSources(kind='SOURCING')` доступен для дальнейшего сопоставления спецификаций. Существующее сравнение цен КП и финансовый движок продолжают выполнять расчёты детерминированно.

Неподтверждённые цитаты и числа отмечаются для ручной проверки. Количество без доказательства не подставляется в расчёт (значение 0 означает отсутствие подтверждённого количества), цена без доказательства остаётся `null`. Для цены нужны ценовой контекст/валюта, для количества — соответствующий контекст/единица. AI-позиции и требования сохраняются неподтверждёнными. Совпадение цитаты не доказывает правильность её толкования: окончательное решение принимает специалист.

## Запуск на Windows / локальном хосте

1. Установите Ollama с [официального сайта](https://ollama.com/download). Node/PostgreSQL и базовые настройки приложения описаны в README.
2. В отдельном терминале запустите только локальный сервер:

```powershell
$env:OLLAMA_HOST='127.0.0.1:11434'
$env:OLLAMA_NO_CLOUD='1'
$env:OLLAMA_NUM_PARALLEL='1'
$env:OLLAMA_MAX_LOADED_MODELS='1'
$env:OLLAMA_MAX_QUEUE='8'
$env:OLLAMA_FLASH_ATTENTION='1'
$env:OLLAMA_KV_CACHE_TYPE='q8_0'
$env:LLAMA_ARG_CACHE_RAM='256'
ollama serve
```

Если Ollama уже запущена приложением в трее, сначала завершите именно этот сервер и перезапустите с выбранными параметрами. Не запускайте два сервера на одном порту.

3. В другом терминале администратор **явно** устанавливает нужную модель:

```powershell
ollama pull qwen3:8b
# При необходимости, отдельным действием:
ollama pull qwen3:4b
ollama list
```

Это загрузки приблизительно 5,2 / 2,5 ГБ; уже установленные модели повторно загружать не требуется. Размер образа модели не равен потреблению памяти. Теги и доступные варианты: [официальная библиотека Qwen3](https://ollama.com/library/qwen3).

4. В `.env` приложения:

```dotenv
AI_PROVIDER=ollama
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODEL=qwen3:8b
AI_EXTERNAL_TRANSFER_APPROVED=false
AI_DAILY_TOKEN_BUDGET=2000000
AI_COMPANY_DAILY_TOKEN_BUDGET=500000
```

При обновлении старой конфигурации замените прежние нулевые AI-бюджеты положительными ограничениями. Ноль закрывает AI, включая локальный: бесплатный inference тоже расходует ресурсы сервера.

```sh
npm ci
npm run db:generate
npm run db:deploy
npm run db:seed
npx tsx scripts/check-local-ai.ts
npm run dev
```

CLI проверяет только локальный provider, наличие модели и реальный структурированный ответ. Он не загружает модель. Рабочие AI-вызовы приложения дополнительно требуют сессии, MFA/права записи, квот и общей SQL-lease.

## Docker: Next.js + PostgreSQL + Ollama

Скопируйте `.env.example` в `.env`, задайте пароли PostgreSQL/ограниченной роли, `SESSION_SECRET`, `DOCUMENT_ENCRYPTION_KEY`, `APP_URL`. Для production-загрузки документов настройте настоящий ClamAV через `CLAMAV_HOST`: существующее требование `CLEAN` сохранено. Тестовый stub из испытаний не является антивирусом и в поставляемой Compose-конфигурации отсутствует.

Явная установка модели администратором, отдельно от обычного запуска:

```sh
docker compose -f docker-compose.yml -f docker-compose.model-install.yml run --rm --no-deps model-install qwen3:8b
docker compose up -d --build
```

Временный installer имеет доступ в Интернет и только к тому моделей. Рабочий Ollama подключён исключительно к `ai-private` (`internal: true`), порт 11434 не опубликован, облачные функции выключены. Модели сохраняются в `ollama-models`. После установки installer завершается. Next.js опубликован на `127.0.0.1:3000`; PostgreSQL наружу не опубликован.

Для NVIDIA GPU с настроенным Container Toolkit:

```sh
docker compose -f docker-compose.yml -f docker-compose.gpu.yml up -d --build
```

Без GPU запускается базовая конфигурация. Для backend без поддержки выбранного KV/attention режима задайте `OLLAMA_FLASH_ATTENTION=0`, `OLLAMA_KV_CACHE_TYPE=f16` и перезапустите сервис. Ограничение памяти контейнера — `OLLAMA_MEMORY_LIMIT`, по умолчанию 16 ГиБ; оно не является гарантией достаточности памяти для любой нагрузки.

`ollama list` в container health check подтверждает доступность сервера. Наличие **выбранной** модели и тест генерации дополнительно проверяются в панели. Приложение может запуститься при недоступном Ollama: финансовые и ручные функции остаются доступны, AI возвращает понятную ошибку. Docker runtime на машине испытаний отсутствовал; Compose проверен статически, запуск контейнеров ещё требуется проверить на целевом хосте.

## Панель «AI-модель»

Настройки → AI-модель доступны OWNER/ADMIN после авторизации и установленной политики MFA. Панель показывает provider, модель, ограничения и результат кнопки «Проверить подключение». `GET/POST /api/settings/ai` закрыты для обычных ролей; внутренний URL и секреты в ответы не включаются. Проверка Anthropic обозначена как платная.

Провайдер глобален для сервера. Его меняет администратор инфраструктуры через защищённую конфигурацию и перезапуск, а не администратор одной компании через общий переключатель. API отвергает попытку передать URL/provider в теле проверки. Все пользователи с доступом к результатам своей компании могут читать её сохранённые фрагменты; чужие задания возвращают 404.

## Ограничения и большие документы

По умолчанию: контекст 16384 токена, ответ до 2048 токенов, 180 секунд на генерацию, 10 секунд ожидания очереди, один параллельный вызов на платформу и один на компанию; 100 вызовов в сутки на компанию. Ограничения задаются сервером, перечислены в `.env.example` и валидируются. Квоты на токены резервируются консервативно до обращения к модели; неудачный запрос тоже расходует резерв.

Документы делятся на последовательные перекрывающиеся фрагменты. Размер зависит от схемы/промпта и бюджета контекста; заголовок и JSON Schema учитываются. Контекст оценивается с запасом по UTF-8 байтам. Все символы выбранных документов покрываются либо задание явно отклоняется до обработки. Ограничения — 250000 символов входа, 40 фрагментов и 10 минут на длинный анализ; фактический допустимый объём может быть меньше из-за схемы и лимита фрагментов. Текст не обрезается молча.

`ai_analysis_jobs` / `ai_analysis_chunks` хранят прогресс и проверенные промежуточные результаты, хеши источников, provider/model digest, версию промпта и ограничения. Сырой непроверенный JSON туда не записывается. Неполное задание получает PARTIAL/FAILED, бизнес-результаты целиком не публикуются как успешные. При смене модели/digest между фрагментами объединение запрещено. При аварии процесса зависшее задание помечается прерванным при следующем чтении статуса.

Очередь — ограниченное ожидание SQL-lease в текущем запросе, общая между репликами. Автономного фонового планировщика/автоматического продолжения после перезапуска нет. Отмена HTTP-запроса передаётся генерации. Фрагменты можно прочесть через `/api/settings/ai/jobs?id=JOB_ID&position=0` и далее по позиции; большие результаты выдаются по одному фрагменту. После прерывания специалист проверяет сохранённое и повторяет нужное задание. Самостоятельные документы большого размера следует разделять по смысловым разделам.

Для compliance разрозненные/противоречивые выводы и отсутствие доказательств в частях не превращаются в уверенный NOT_FOUND. Зависимости между фрагментами могут быть потеряны; это явно попадает в ограничения. Повторяющиеся позиции сохраняются для проверки, без молчаливого объединения количеств.

## Безопасность и размещение данных

- URL выбирается только сервером: разрешены фиксированные loopback-адреса и Docker-сервис `ollama` на 11434; query, credentials, дополнительные пути, другие хосты и redirects запрещены. `localhost` закрепляется за 127.0.0.1. Имя `ollama` должно разрешаться исключительно доверенным Docker DNS; сеть не должна быть доступна недоверенным контейнерам.
- Разрешены локальные `qwen3:4b` / `qwen3:8b`; remote/cloud model aliases отклоняются через `/api/show`, `OLLAMA_NO_CLOUD=1` и отсутствие внешнего маршрута Docker-сервиса. Обновление образа/модели — действие администратора.
- Секреты окружения не включаются в промпт. Типовые токены API/приватные ключи и известные инструкции подмены в документе блокируются. Это дополнительная защита от известных шаблонов, а не доказательство обнаружения всех prompt-injection атак. У модели нет инструментов исполнения кода, отправки сообщений или изменения настроек.
- Ошибки provider не сохраняют raw payload и текст документа; размер ответа ограничен по фактическому потоку. Обычные логи не должны содержать промпты/ответы; `OLLAMA_DEBUG_LOG_REQUESTS=false`. Диагностические подробности не выводятся пользователю.
- Существующие tenant-фильтры, сессии, MFA и RLS сохранены. Новые таблицы прогресса и их дочерние результаты также защищены RLS. Сервис работает под NOBYPASSRLS-ролью. Промежуточные результаты содержат цитаты: защита и сроки хранения БД/резервных копий должны соответствовать защите исходных документов.

Локальный режим означает отсутствие зарубежного AI-вызова, но не устанавливает географию хоста. Статья 12 [Закона РК о персональных данных](https://old.adilet.zan.kz/rus/docs/Z1300000094) требует хранения базы/цифрового объекта в Казахстане; статья 16 регулирует трансграничную передачу. До обработки персональных данных владелец должен подтвердить физическое размещение приложения, Ollama, БД и резервных копий, законное основание обработки и сроки хранения. Код не удостоверяет юридическое соответствие инфраструктуры.

## Явное переключение на Anthropic

Только после разрешения владельца, проверки правового основания и настройки внешних квот:

```dotenv
AI_PROVIDER=anthropic
ANTHROPIC_API_KEY=...секрет_только_на_сервере...
ANTHROPIC_MODEL=...доступная_владельцу_модель...
AI_EXTERNAL_TRANSFER_APPROVED=true
AI_DAILY_TOKEN_BUDGET=...положительный_лимит...
AI_COMPANY_DAILY_TOKEN_BUDGET=...положительный_лимит...
```

Перезапустите приложение. Для возврата установите `AI_PROVIDER=ollama`, `AI_EXTERNAL_TRANSFER_APPROVED=false` и перезапустите. Ошибка локальной модели никогда не меняет provider. Платные API в испытаниях не вызывались.

## Проверка и воспроизведение

```sh
npm run verify
npm run build
npx tsx scripts/check-local-ai.ts
# На отдельной локальной БД/сервере с реальными моделями:
# AI_LIVE_TEST=true E2E_PUBLIC_SPEC_PATH=/absolute/public.pdf
npx playwright test tests/local-ai.spec.ts
# Корпус: публичные PDF, URLs, выбранные страницы и контрольные требования:
npx tsx scripts/evaluate-local-ai.ts manifest.json report.json
```

Пример manifest и измерения: [отчёт испытаний](local-ai-evaluation.md), `docs/local-ai-corpus.example.json`. Скрипты не скачивают файлы/модели. Корпус и результаты с документами клиентов не коммитятся. Качество на реальных спецификациях, память CPU/GPU, ограничения эксперимента и непроверенные части перечислены в отчёте.

Официальные API: [chat](https://docs.ollama.com/api/chat), [structured outputs](https://docs.ollama.com/capabilities/structured-outputs), [память, Flash Attention и cloud disable](https://docs.ollama.com/faq).
