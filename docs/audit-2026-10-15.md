## Реализованные модули

Есть регистрация компании, серверные сессии с отзывом, роли, CRUD тендеров,
загрузка PDF/DOCX/XLSX, извлечение текста, предложения поставщиков,
детерминированные расчёты, ДДС, сценарии, импорт исторических CSV/XLSX,
отчёт PDF и сохранение JSON-снимка. AI использует существующий серверный
Anthropic SDK; без ключа возвращает явную недоступность.

Наличие кода не подтверждает работоспособность каждого полного сценария.
Предыдущие утверждения `docs/status.md` о полной готовности не принимаются
как результаты этого аудита.

## Подтверждённые дефекты для исправления

1. `api/tenders/[id]/finance`: обновление по чужому `modelId` не связано
   с проверенным тендером. Требуется атомарная проверка родителя/компании.
2. `api/settings/taxes`: OWNER новой компании может менять общий налоговый
   справочник. Требуется изоляция пользовательских корректировок компании.
3. Login/register не проверяют Origin и media type перед установкой cookie.
4. Вход/регистрация не ограничивают попытки; дорогие AI-вызовы не имеют
   общего лимита организации/платформы.
5. Парсеры Office раскрывают ZIP целиком до ограничений строк результата;
   нет лимитов распаковки и отдельного процесса обработки.
6. MIME/расширение не подтверждаются сигнатурой файла; multipart целиком
   читается до проверки размера; антивирус/карантин отсутствуют.
7. Валютная цена выбранного КП попадает в финансовую модель без FX-конвертации.
   Также теряются признак НДС, срок действия и подтверждённость предложения.
8. `money.ts` возвращает 0 для NaN/Infinity; операции используют floating point
   без контроля переполнения. Вход допускает отрицательные цены тендера.
9. Ошибки API отдают клиенту исходный текст исключения; Docker Compose
   публикует PostgreSQL и имеет пароль `postgres` по умолчанию.
10. Seed перезаписывает существующие налоговые записи при каждом запуске.

## Пробелы задания и внешние зависимости

MFA/passkeys, PostgreSQL RLS, приглашения и управление членством, квоты SaaS,
платежи, уведомления, OCR, импорт ZIP-комплекта, автоматическое извлечение КП,
локальный AI, резервное копирование с проверкой восстановления и независимая
правовая/безопасностная проверка ещё требуют реализации или проверки.

Для AI нужен настроенный провайдер и основание передачи данных. Для production
нужны инфраструктура и резервные копии в Казахстане, TLS, менеджер секретов,
антивирус, политика хранения и доступы владельца. Автоматический сбор с порталов
не должен обходить CAPTCHA или ограничения доступа.

## Источники и пределы проверки

Конфигурация Prisma должна позволять `generate` без DATABASE_URL, сохраняя
обязательность реального подключения для миграций:
[официальная документация Prisma](https://docs.prisma.io/docs/orm/reference/prisma-config-reference).

Официальный закон РК [«О персональных данных и их защите»](https://adilet.zan.kz/rus/docs/Z1300000094)
проверялся 15.10.2026 через официальный поисковый индекс: ст. 12 относится
к хранению в Казахстане, ст. 16 — к трансграничной передаче. Полный текст
страницы напрямую не загрузился. Юридическое соответствие этим не подтверждено;
актуальную редакцию и применимость должен проверить юрист до клиентских данных.

Аудит исходной версии фиксирует состояние ДО исправлений. Статус исправлений,
точные команды, результаты и оставшиеся ограничения публикуются отдельно.
