# Изменения этапа 1

Реализованы привязка FinancialModel к компании и URL-тендеру, отдельные
налоговые корректировки компаний, серверная сборка налогового контекста,
Origin/media-type-проверка API, ограниченное чтение JSON/multipart, общие
атомарные квоты PostgreSQL, Argon2id с миграцией bcrypt при успешном входе,
безопасные сообщения об ошибках, HTTP-заголовки и закрытый порт PostgreSQL.

Office-файлы проверяются по структуре контейнера и фактической распаковке:
до 2000 элементов, суммарно 50 MiB, до 20 MiB на элемент, ограничение
коэффициента сжатия. Макросы/вложения и дублирующиеся/опасные пути отклоняются.
Старый XLS явно не поддерживается — его нужно пересохранить в XLSX.

Парсер работает в отдельном V8 worker с 192 MiB heap и сроком 30 секунд;
его окружение не получает ключей/подключения БД. Это ограничение ресурсов,
а не полноценная OS-песочница: нативная память и уязвимости сторонних библиотек
потребуют отдельного контейнера/службы до production.

Файл не записывается и не передаётся парсеру до ответа CLEAN от ClamAV.
Отсутствующий/недоступный scanner блокирует production-загрузку. В development
без scanner возможна обработка с явным предупреждением UNSCANNED; для реальных
данных задайте DOCUMENT_SCAN_MODE=required. Infected-файлы отклоняются, отдельный
постоянный карантин и административный release-процесс ещё не реализованы.

AI по умолчанию отключён: кроме ключа необходимы подтверждённое основание
передачи данных и AI_EXTERNAL_TRANSFER_APPROVED=true, а также оба положительных
token budget. До каждого вызова атомарно резервируется верхняя оценка токенов
(UTF-8 bytes входа + максимальный output); резерв не возвращается при ошибках,
чтобы повторы не обходили лимит. SDK может повторить сетевой запрос до двух раз:
перед production отключите автоматические повторы или учитывайте их в бюджете.
Есть лимит 20 вызовов/компанию/сутки и общий бюджет платформы.

Негативные API-тесты запускаются только на loopback и отдельной локальной БД:

```sh
npm ci
npm run db:generate
npm run db:deploy
npm run db:seed
npm run verify
npm run dev
# в отдельном терминале с тем же DATABASE_URL и APP_URL
npm run test:e2e -- tests/security.spec.ts
```

Выполнено на 15.10.2026: 225 unit/integration тестов PASS, 5 HTTP-тестов PASS,
TypeScript PASS, ESLint PASS. Проверены чужие tenant/model IDs, неизменность чужой
модели и общего справочника, подмена налогового контекста, Origin/content type,
лимит попыток, плохой JSON, роль VIEWER и отзыв сессии. Это не подтверждает
выполнение всех требований ASVS или готовность к клиентским данным.

Остаются MFA/passkeys, принудительная MFA администраторов, RLS и DB-роли,
изолированный parser service, шифрование/ротация ключей, backup/restore,
идемпотентность/конкурентность AI и независимая проверка. Docker не запускался:
Docker engine на рабочей машине не обнаружен.
