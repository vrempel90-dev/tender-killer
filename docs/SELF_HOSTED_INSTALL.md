# TENDER KILLER — автономная установка без платных AI API

> Версия документа: 17.10.2026. Инструкция относится к ветке `chatgpt/self-hosted-no-paid-ai-20261017`. **Не считать подтверждением production-готовности**: запуск Compose на целевом сервере должен быть проверен отдельно.

## Что бесплатно, а что нет

Приложение использует локальную Ollama + Qwen3 (4B или 8B). **Для анализа нет требований к API-ключам OpenAI, Codex или Anthropic, нет оплаты за токены и нет платного fallback.** Финансовый расчёт выполняется обычным кодом. Сторонние библиотеки и модели имеют собственные лицензии; проверьте их перед коммерческой перепродажей и распространением.

Сервер/компьютер, электроэнергия, домен, резервные копии и почтовый провайдер могут стоить денег. Railway Pro **не предоставляет безлимитные бесплатные CPU/RAM**: в подписку включён ограниченный бюджет. Не создавайте там AI-сервис без расчёта общего расхода.

## Аппаратные требования

Ориентиры, не гарантии производительности:

- Qwen3 4B: выделенный сервер от **16 ГБ RAM**, предпочтительно 4+ ядра и SSD. `OLLAMA_MEMORY_LIMIT=8g`, модель `qwen3:4b`. При CPU-only сложные документы будут обрабатываться медленно.
- Qwen3 8B: предпочтительно **32 ГБ RAM** и GPU с подходящим объёмом VRAM; по умолчанию `OLLAMA_MEMORY_LIMIT=16g`, модель `qwen3:8b`.
- ClamAV: резервируйте до 4 ГБ RAM, следите за обновлением сигнатур. Диск: минимум 20 ГБ свободно плюс запас под документы, PostgreSQL и резервные копии. Сама 4B модель скачивает около 2,5 ГБ, 8B — около 5,2 ГБ.

На одном сервере одновременно работают веб-приложение, БД, AI и антивирус. Реальная нагрузка и память зависят от объёма документов и параллельных запросов. Для коммерческого трафика необходимы замеры.

## 1. Первичная настройка

Нужны Docker Engine + Docker Compose v2 и сетевой доступ **только на этапе** загрузки Docker-образов, модели и обновлений сигнатур ClamAV. Для изолированной сети заранее подготовьте образы, модель и базы антивируса.

```bash
git clone https://github.com/vrempel90-dev/tender-killer.git
cd tender-killer
git switch chatgpt/self-hosted-no-paid-ai-20261017
cp .env.example .env
chmod 600 .env
```

Сгенерируйте **отдельные случайные** значения:

```bash
openssl rand -hex 24      # POSTGRES_PASSWORD
openssl rand -hex 24      # APP_DB_PASSWORD (НЕ использовать тот же пароль)
openssl rand -base64 48   # SESSION_SECRET
openssl rand -base64 32   # DOCUMENT_ENCRYPTION_KEY
```

Поместите их в `.env`. Для паролей PostgreSQL в Compose используйте URL-безопасные символы (например, hex); если используете иные символы, они должны быть корректно percent-encoded в URL подключения. `APP_DB_PASSWORD` — минимум 16 символов.

Дополнительно установите:

```dotenv
APP_URL="http://localhost:3000"
AI_PROVIDER="ollama"
OLLAMA_MODEL="qwen3:4b"
OLLAMA_MEMORY_LIMIT="8g"
EMAIL_PROVIDER="resend"
EMAIL_DOMAIN_VERIFIED="false"
```

Выше **пример для локальной демонстрации**, не для публичного сервера. Для доступного извне сервиса требуется доверенный HTTPS reverse proxy и `APP_URL=https://ваш-домен`. Не открывайте порт 3000 напрямую в Интернет, используйте ограничение на уровне reverse proxy/firewall.

`DATABASE_URL` и `APP_DATABASE_URL` в .env используются для ручных команд и тестов, Compose самостоятельно формирует URL подключения из `POSTGRES_PASSWORD` и `APP_DB_PASSWORD`. Не путайте их с production Railway. Не подключайте контейнеры к существующей базе без инвентаризации и проверенной резервной копии.

## 2. Проверка конфигурации и запуск

```bash
docker compose config --quiet
docker compose up -d --build
docker compose ps
```

На первом запуске **миграции и справочник ставок** выполняются одноразовым `migrate` контейнером, затем `db-roles` создаёт ограниченную роль с RLS. Веб-приложение ждёт исправную БД, успешные миграции, роль и **реальный ClamAV**. Антивирусу может понадобиться несколько минут для начального получения сигнатур.

```bash
docker compose logs --tail=100 app db migrate db-roles clamav ollama
curl --fail http://127.0.0.1:3000/api/health
```

Не публикуйте эти логи без проверки: в них может быть служебная информация.

**Структура сетей:** `db-private`, `ai-private`, `scan-private` — внутренние сети Docker. У ClamAV есть **отдельная исходящая** сеть `av-updates` для FreshClam: она нужна для обновления антивирусных сигнатур, но не публикует порт ClamAV наружу. Для полностью изолированной инсталляции потребуется отдельно загрузить и регулярно обновлять подписанные базы ClamAV — иначе не обещайте актуальную антивирусную защиту. Порты БД, Ollama и ClamAV наружу не публикуются. Приложение публикует только `127.0.0.1:3000`. Модели и данные хранятся в отдельных постоянных Docker volumes.

## 3. Установка Ollama-модели отдельной командой

**Модель не загружается при сборке или каждом рестарте.** Явное действие администратора:

```bash
docker compose -f docker-compose.yml -f docker-compose.model-install.yml run --rm --no-deps model-install qwen3:4b
docker compose exec ollama ollama list
docker compose exec ollama ollama run qwen3:4b 'Ответь одним словом: ГОТОВО'
```

Для 8B поменяйте `OLLAMA_MODEL=qwen3:8b` и `OLLAMA_MEMORY_LIMIT=16g` в `.env`, затем установите `qwen3:8b`. При изменении переменных перезапустите соответствующие сервисы с `docker compose up -d`. Не ожидайте, что Ollama сама переключит модель при её отсутствии.

В приложении OWNER/ADMIN открывает **Настройки → AI-модель → Проверить подключение**. Нужны права/MFA. Тест через UI должен подтверждать наличие выбранной модели и реальный ответ, а не только открытый порт.

## 4. Что работает без внешних API

- Финансовый движок, денежный поток, сценарии и отчёты.
- Загрузка документов, извлечение текстового слоя PDF/DOCX/XLSX с проверкой ClamAV.
- AI Compliance, AI Sourcing, Contract Risk — при работающей Qwen3. Результаты AI требуют проверки человеком.
- Tender Intelligence, RADAR — на загруженных пользователем CSV/XLSX.
- GUARD — сравнение **загруженных пользователем** версий документов и условий.
- Регистрация, роли, MFA; восстановление пароля — **только после настройки реальной почты**.

**Не работают автоматически без внешнего источника:** поиск новых закупок на портале и получение изменений из него. Требуется законный официальный API-токен, либо регулярный импорт из выгрузок. Никаких скрытых платных AI API и вымышленных закупок нет.

**Сканированные PDF** без текстового слоя требуют OCR; данный комплект не обещает OCR. Поставщиков и цены, не подтверждённые документами/КП, AI не выдумывает.

## 5. Email и пароль

Сброс пароля реализован, но **не может отправлять настоящие письма без подтверждённого отправителя**. Для активации требуется настроить Resend (у него есть бесплатный план с ограничениями) и DNS домена. Установите `EMAIL_FROM`, `RESEND_API_KEY`, `EMAIL_DOMAIN_VERIFIED=true` **только после** фактической проверки домена. Подробности — [password-reset.md](password-reset.md). Утверждать, что доставка работает, до контролируемой проверки почтового ящика нельзя.

Проверка локальных тестов почты использует `APP_ENV=test`, sink на loopback и синтетические email, никогда не включайте этот тестовый транспорт в публичном окружении.

## 6. Проверки перед передачей покупателю

```bash
docker compose ps
docker compose exec ollama ollama list
docker compose exec clamav clamdscan --ping=1
curl --fail http://127.0.0.1:3000/api/health
```

На машине разработчика (при наличии Node.js 22/npm):

```bash
npm ci
npm run verify
npm run build
```

Автопроверка Docker Compose включена в GitHub Actions: она проверяет приватные сети, отсутствие API-ключей платного AI, обязательный сканер и постоянные тома. **Успешный CI не заменяет тесты на сервере покупателя**.

## 7. Данные, резервные копии и ответственность

Не передавайте покупателю реальные пользователи/документы без отдельного законного основания. Для начальной установки должна использоваться **пустая база данных**. Не копируйте production `.env`, ключи, токены, тома, PostgreSQL dump или аккаунты Railway.

Для эксплуатации необходимо настроить:
1. шифрованный backup PostgreSQL и файлового тома; `DOCUMENT_ENCRYPTION_KEY` хранить отдельно от копии, с отдельным защищённым резервированием ключа;
2. восстановление в отдельную пустую БД и проверку файлов;
3. мониторинг свободного диска, ошибок Ollama/ClamAV и обновления сигнатур;
4. HTTPS, firewall, резервное копирование ключей и политику обновлений;
5. местоположение персональных данных с учётом законодательства РК.

Есть скрипты `scripts/backup.sh` / `scripts/backup-verify.sh`, но они требуют настройки путей и поддерживаемой версии `pg_dump` **вне Compose**. Не считайте backup настроенным автоматически.
