# Решения по зависимостям и аудиту

Документ фиксирует, почему состав зависимостей именно такой, и на каких
условиях решения пересматриваются. Правило проекта: **gate аудита не
подавляется и не ослабляется ради зелёной сборки**. Уязвимость либо
устраняется, либо зависимость удаляется.

Состояние на 15.10.2026: `npm audit` — **0 уязвимостей** (полный аудит,
включая dev-зависимости).

---

## 1. Удалён `@next/eslint-plugin-next`

**Что было.** Плагин давал правила Next.js (`no-img-element`,
`no-sync-scripts`, `google-font-display` и др.) и блокировал CI.

**Проблема.** Версии 15–16 зависят от `fast-glob` → `micromatch` → `braces`.
Для `braces` действует advisory
[GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm)
(high, stack exhaustion через глубоко вложенные шаблоны), и исправленной
версии не выпущено: уязвимы **все** опубликованные версии, включая
последнюю 3.0.3.

**Что проверено перед удалением.**

| Вариант | Результат |
| --- | --- |
| Override `braces` / `micromatch` на исправленную версию | Невозможно: исправленной версии нет |
| Откат плагина на 14.2.35 (использует `glob`, не `fast-glob`) | `glob@10.3.10` сам уязвим (GHSA-5j98-mcp5-4vw2); после override на `glob@^10.5.0` аудит чист, но плагин вызывает удалённый в ESLint 9 API `context.getAncestors()` и падает на **любом** файле с JSX |
| Подавить advisory в CI | Отклонено: нарушает правило проекта |

**Решение.** Зависимость удалена. Применимые к этому проекту проверки
воспроизведены в `eslint.config.mjs` через `no-restricted-syntax`:

| Правило плагина | Замена | Проверено |
| --- | --- | --- |
| `no-img-element` | селектор `JSXOpeningElement[name.name='img']` | да, ловит `<img>` |
| `no-sync-scripts` | `<script>` без `async`/`defer` | да, ловит внешний скрипт |
| `google-font-display` | `<link href="…fonts.googleapis.com…">` | да, ловит ручной `<link>` |
| `no-head-element` | селектор `JSXOpeningElement[name.name='head']` | да |

**Что потеряно.** Правила, завязанные на структуру каталога `pages`
(`no-html-link-for-pages`), и предупреждения о новых API Next. Проект
использует App Router и каталога `pages` не имеет, поэтому первые
неприменимы.

**Условие возврата.** Плагин возвращается, когда выйдет версия, не тянущая
уязвимую цепочку, либо когда `braces` получит исправление. Проверять при
каждом обновлении Next.js.

## 3. Override `argparse` → `^3.0.2`

**Проблема.** `mammoth` (парсер DOCX, runtime-зависимость) тянет
`argparse@1.x`, который зависит от уязвимого `sprintf-js`
([GHSA-hp3w-g68c-fv3c](https://github.com/advisories/GHSA-hp3w-g68c-fv3c),
moderate).

**Проверка.** `argparse` в `mammoth` встречается только в `bin/mammoth`
(интерфейс командной строки). Код библиотеки, который использует
приложение, его не импортирует:

```
grep -rl "argparse" node_modules/mammoth/
→ node_modules/mammoth/NEWS
→ node_modules/mammoth/package.json
→ node_modules/mammoth/bin/mammoth      ← только CLI
```

**Решение.** Override на `argparse@^3.0.2`, который не зависит от
`sprintf-js`. Приложение CLI mammoth не вызывает. Извлечение DOCX
покрыто тестами на реальном файле (`src/lib/documents/__tests__`) — после
override они проходят.

## Порядок работы с новыми находками аудита

1. Проверить, затрагивает ли уязвимость runtime или только сборку.
2. Найти выпущенное исправление: обновление прямой зависимости, затем override.
3. Если исправления нет — оценить, можно ли удалить зависимость или
   заменить её функциональность (как сделано с плагином Next).
4. Подавление advisory недопустимо. Если устранить невозможно, работа
   останавливается и решение выносится владельцу продукта с описанием
   риска и вариантов.
5. Любое принятое решение фиксируется в этом документе с проверкой,
   подтверждающей, что функциональность не пострадала.
